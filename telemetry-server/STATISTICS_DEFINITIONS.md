# MicroGlow 分析后台统计口径（冻结版）

适用任务：`MICROGLOW-ANALYTICS-FREEZE-001`

## 通用规则

- 统计时区统一为 UTC。
- `aggregation_day` 表示 UTC 自然日。
- 统计主体统一称为“安装”；不把匿名 installation hash 解释为注册用户或自然人。
- 所有卡片、图表、版本覆盖、Schema/Consent 覆盖、JSON、CSV 和打印/PDF 均继承当前日期范围。
- 日期范围包含开始日和结束日。
- 未指定结束日时，以筛选结果中的最新数据日为统计截止日。
- 指定结束日时，以该 UTC 日期为统计截止日；即使当天没有数据，DAU 也按该日计算为 0。
- 快捷范围（当天/近 7 天/近 30 天/近 90 天/近 365 天）每次点击都按“筛选结果中的最新数据日”重新计算结束日，不沿用上一次输入的结束日期；因此数据补传后快捷范围会自动前移。

## 活跃安装

- DAU：统计截止 UTC 自然日内至少有一条每日汇总的去重安装数。
- WAU：截至统计截止日（含）的滚动 7 个 UTC 自然日内活跃的去重安装数。
- MAU：截至统计截止日（含）的滚动 30 个 UTC 自然日内活跃的去重安装数。
- 新增安装：首次出现日期位于当前日期范围内，且在范围内活跃的安装。
- 回访安装：首次出现日期早于当前日期范围开始日，且在范围内再次活跃的安装。
- 未指定开始日时，开始日取筛选结果中的最早数据日。

## 留存

- 7 日留存：安装在首次活跃后的精确第 7 个 UTC 自然日再次活跃。
- 30 日留存：安装在首次活跃后的精确第 30 个 UTC 自然日再次活跃。
- 不用第 7–13 天或第 30–44 天的窗口替代精确留存。
- 尚未经过对应观察期的安装不进入分母。
- 分母为 0 时 API 返回 `null`，界面显示“数据不足”；可计算但无人留存时才显示 `0.0%`。

## 调用、Token 与活跃分钟

- 调用总量等于 `api_call_count`，包含成功和失败请求。
- 数据接收时强制 `success_count + error_count = api_call_count`。
- Token 总量等于输入 Token 加输出 Token。
- 数据接收时强制 `input_tokens + output_tokens = total_tokens`。
- 每安装平均调用 = 日期范围内调用总量 ÷ 日期范围内活跃安装数。
- 每安装平均 Token = 日期范围内总 Token ÷ 日期范围内活跃安装数。
- 每安装平均活跃分钟 = 日期范围内活跃分钟总量 ÷ 日期范围内活跃安装数。
- Provider/Model 调用份额 = 该 Provider/Model 调用次数 ÷ 范围内调用总量。
- Provider/Model Token 份额 = 该 Provider/Model 的输入与输出 Token 之和 ÷ 范围内总 Token。

## 分位数

- 计算单位是“每个活跃安装在当前日期范围内的累计量”。
- P50 最少需要 2 个活跃安装。
- P90 最少需要 10 个活跃安装。
- P99 最少需要 100 个活跃安装。
- 未达到最小样本量时 API 返回 `null`，界面显示“样本不足”。
- 界面在每个均值和分位数旁显示当前样本数 `n`。

## Schema v2 质量指标

延迟区间固定为：

- `lt_1s`：小于 1 秒。
- `from_1s_to_3s`：大于等于 1 秒且小于 3 秒。
- `from_3s_to_10s`：大于等于 3 秒且小于 10 秒。
- `gte_10s`：大于等于 10 秒。

四个延迟区间计数之和必须等于 `api_call_count`。

错误类别固定为：

- `authentication`
- `rate_limit`
- `timeout`
- `unavailable`
- `invalid_request`
- `other`

错误类别计数之和必须等于 `error_count`。服务不接收原始错误消息。

`fallback_count` 是日期范围内发生 Provider/Model 回退的次数汇总，不得超过调用次数。

## Consent 协议

- schema v1 只接受服务端配置的 `CONSENT_VERSION_V1` 精确值。
- schema v2 只接受服务端配置的 `CONSENT_VERSION_V2` 精确值。
- 缺失、为 false、已撤回或不匹配的 Consent 均拒绝接收。
- 只匹配 `v2` 前缀不构成有效同意；版本必须完整精确匹配。
- 被拒绝的批次不会写入服务端数据库，也不会收到成功 ACK。
- 客户端只有收到匹配 batch ID 的成功 ACK 后才能删除本地批次；拒绝或失败时保留到下一次正常上传。

## 数据质量时间

- 生成时间：管理员汇总响应生成时的 UTC 时间。
- 最后成功接收时间：当前筛选日期范围内，服务端最近一次成功写入批次的 UTC 时间。
- 数据截止时间：当前筛选范围中最新的 `aggregation_day`。
- 数据延迟：当前 UTC 日期减去数据截止日期的自然日数。

## 导出

- JSON 导出使用当前已筛选的完整 API 响应。
- CSV 导出使用当前筛选后的每日序列。
- CSV 包含生成时间、UTC、日期范围、Schema/Consent 覆盖和核心统计口径。
- 打印/PDF 使用当前页面状态，并显示当前日期范围、UTC 和冻结口径。
