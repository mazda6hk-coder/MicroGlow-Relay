# Security policy

## Reporting a vulnerability

Please email **security@microglow.com.cn** with:

- a description of the issue and its impact;
- the affected version (visible in the app's About page or `src/storage.py`);
- reproduction steps, if available.

Please do not open a public issue for a vulnerability, and do not attach real
API keys, tokens, prompt contents or conversation data. Use synthetic values.

We will acknowledge your report and coordinate disclosure. We do not run a paid
bug bounty program.

## Supported versions

Security fixes are provided for the latest published release. Older versions
may not receive fixes.

## Scope

In scope:

- the local HTTP gateway (`src/server.py`, `src/adapters.py`, `src/channels.py`);
- credential storage and local access token handling (`src/storage.py`);
- client configuration writing and restore (`src/codex_config.py`,
  `src/claude_config.py`);
- the installer and update-check logic (`installer/`, `app/updates.py`,
  `app/update_controller.py`);
- the telemetry ingestion service (`telemetry-server/`).

Out of scope:

- vulnerabilities in third-party model providers or clients;
- issues that require the user to run untrusted code or hand over their API keys;
- reports produced solely by automated scanners without a practical impact.

## Known limitations (security-relevant)

- The Windows installer is **not code-signed**. Windows may show a SmartScreen
  warning. Verify the SHA-256 checksum published with the release.
- Anonymous telemetry is opt-in and off by default. Update checks are on by
  default and contact GitHub and the project website; see `docs/PRIVACY-POLICY.md`.
- The local access token is generated by Relay and stored encrypted with Windows
  DPAPI in Relay's own settings. To let Codex and Claude Code connect, that token
  is written in plain text into those clients' own configuration files; this is
  required by their configuration formats.
