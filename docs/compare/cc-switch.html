Relay vs. cc-switch

They solve adjacent problems. One switches which configuration a client reads; the other runs a local service that the client talks to. Choosing depends on whether you want to manage configurations or manage traffic.

 cc-switchMicroGlow Relay
ShapeDesktop configuration switcherLocal gateway on 127.0.0.1:4141
What changesWhich provider configuration the client readsNothing in the client beyond one endpoint and token
Switching providersSwitch the active configurationSwitch models or channels inside Relay; the client stays pointed at Relay
FailoverNot its main job; you switchWeighted channels, 60-second cooldown, failover before the response starts
Usage metering—Trip Token: two subtotals, scope per client, undoable reset, ledger
InterfaceUtility-firstSeasonal and day/night skins; eight interface languages

Descriptions reflect each project's public positioning as of late 2026 and the category they occupy; details change over time. Check each project's own documentation before deciding.

Choose cc-switch if…

  • you only need to switch between provider configurations, and a restart is acceptable;
  • you do not want a background service running;
  • your workflow is "one provider at a time".

Choose Relay if…

  • you want both Codex and Claude Code pointed at one local endpoint at the same time;
  • you want retries and channel failover handled before the response starts;
  • you want per-session token accounting with a reset you can undo;
  • you care what the tool looks like while you use it.
